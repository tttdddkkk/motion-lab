# 0016: モダン CSS は、対応ブラウザを調べてから使う

- 状態: 採用
- 日付: 2026-11-15

## 背景

モーションは CSS（transition / animation / `clip-path` など）で作っており、新しい CSS 機能を使うほど表現の幅は広がる。一方で、機能はブラウザとバージョンによって対応が異なる。このリポジトリのコードは、利用者が採用した値をコピーして自分の実装に貼る前提（`docs/philosophy.md`）なので、ビューアで動いても、貼り先で動かないと認識合わせの道具として意味を持たない。

AI は新しい機能を「使える」と記憶で答えがちで、対応バージョンも古い・不正確なことがある。ブラウザ差は `docs/philosophy.md` でも、自前で持つのが難しい領域に挙げている。

## 決定

- 新しめの CSS 機能を使う前に、一次情報（MDN の Browser compatibility、Baseline、caniuse）で対応状況を調べる。手順は CLAUDE.md の「モダン CSS を使うときの対応ブラウザ確認」に置く
- 既定の下限は Baseline の Widely available とする。Newly available の機能は `@supports` / `CSS.supports()` による判定と代替を用意したときだけ使う
- 調べた結果（対応開始バージョン、Baseline 区分、調べた日、未対応時の挙動）は PR 本文に残す

## 検討した他の案

- `browserslist` などの対象ブラウザ設定とリンターで機械的に検出する: ビューアにビルド工程を入れない方針（ADR 0002、README）と合わない。件数が増えて手順では追いきれなくなったら再検討する
- 対応ブラウザの一覧をリポジトリに固定して持つ: バージョンは変わり続け、陳腐化する。毎回調べるほうが正確
- 調べずに、実機での確認だけに頼る: iOS Safari など、確認できない環境が残る

## 結果

- 新しい機能を使うときに、調査と PR 本文への記載という手順が1つ増える
- 未対応ブラウザで壊れる表現を、コピーされる前に見つけやすくなる
- 手順に従っているかはテストで検出できない。レビューと作業者の確認に頼る
