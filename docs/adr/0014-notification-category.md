# 0014: 「通知」カテゴリを作り、チャットはコメントに含める

- 状態: 採用
- 日付: 2026-11-14

## 背景

コメント系のモーション（流れる文字、チャットの吹き出しなど）を増やす中で、トーストや新着通知のような別系統の表現が出てきた。カテゴリの境目が曖昧なまま増やすと、一覧で探しにくくなる。

## 決定

次の基準でカテゴリを分ける。

| カテゴリ | 範囲 | 例 |
| --- | --- | --- |
| コメント | 他者の短い発言が並ぶ・流れる。チャットの吹き出しを含む | `flow-seek`、`chat-pop` |
| 通知 | システムや相手からの通知。自動で消えるか、操作で消える | `toast`、`banner-drop`、`badge-pop` |
| テキスト | 1つの文章の見せ方（字幕・ティッカーなど）。カテゴリはまだ作らない | — |

- ビューアの `CATS` に「通知」（`notice`）を足す
- 通知系の見た目は、特定の OS・サービスの通知に寄せない（名前・配色・形）
- 通知系はアプリ画面の上に出す想定で、映像は使わない。ADR 0008 の「映像と重ねない」の対象外だが、固定テキストで、投稿やサーバーの仕組みは作らない点は同じ
- すべて「動きを減らす」版（transform と clip-path を使わない）を用意する
- トーストと新着ピルは、どちらも「画面下の小さな通知で、自動か操作で消える」ため、1件（`toast`）にまとめる
- トーストの入り方の違い（方向: 上下左右、出し方: スライド・フェード・なし）は、`MOTIONS` ではなく差分比較（ADR 0012）の「D. 通知」に置く。`MOTIONS` の表示用コードは1件に1つで、6通りを正しく表せないため
- 差分比較の「なし」は時間 0 で切り替える。時間 0 とイージングなしを許すのは `mode: 'none'` だけで、`tests/compare.test.js` に明記して検査する

## 検討した他の案

- カテゴリ名を「メッセージ」にする: チャット（会話のメッセージ）と紛らわしく、中身（トースト・バナー・バッジ）とも合わないため「通知」にした
- チャットも通知に含める: 通知系と会話系が混ざり、「出て消える」軸と「積み上がる」軸が同じ一覧に並ぶ。チャットは他者の発言が並ぶ点でコメントに近い
- カテゴリを分けずコメントに入れる: トーストやバッジはコメントと用途が違い、一覧で探しにくい

## 結果

- 通知は3件（トースト、バナー、バッジ）から始める。トーストの方向・出し方の違いは差分比較で見る
- トーストは `MOTIONS` と差分比較の両方にあるため、値（入る 300ms・見せる 2.5s・出る 250ms）を変えるときは両方を合わせる
- テキスト系は、件数が増えたらカテゴリを作る
- カテゴリが増えても、軸ごとのグループ化とタグでの絞り込みを保つ方針は変わらない
