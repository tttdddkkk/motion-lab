# 0022: スマホ幅では、プレビューを画面上部に固定し、一覧を折りたためるようにする

- 状態: 採用
- 日付: 2026-11-18

## 背景

スマホ幅（820px 以下）では 1 カラムになり、一覧（`aside`）が先、プレビューが後に並ぶ。モーションを選ぶたびに、一覧の下にあるプレビューまでスクロールが要った。見比べて選ぶ道具なので、選んだ結果がすぐ見えないと使いにくい。

## 決定

- スマホ幅では `aside` / `#viewer` / `.stage-wrap` を `display: contents` にして、中身を `.app` の直下に並べ直し、`order` で「ブランド、モード切替、**プレビュー（固定）**、一覧、タイトル、詳細、コード」の順にする。プレビュー（`.preview`）は `position: sticky; top: 0`
- 固定するプレビューは、`.phone` を `--s` 倍（0.55。背が低い画面は 0.42）に縮める。拡大縮小は `transform: scale()`
- 縮小表示では、`getBoundingClientRect()` と `clientX` の座標が縮んで、デモ内の px とずれる（リップルの位置、本棚の移動量）。`runtime.js` の `scaleOf(stage)` で割って補正する。表示用コード（`code.*`）は、縮小しない実装の値のまま変えない
- 「原寸」ボタンで、同じ DOM のまま画面全体に重ねて実寸（260×480）で表示する。閉じるボタン、背景のタップ、Esc で戻る。再生は途切れない
- 一覧は `<details>` で折りたためる。タグは 1 行の横スクロールにする。広い画面では見出しを出さず、常に開く
- 広い画面（821px 以上）の見た目は変えない（変更前後のスクリーンショットが一致することを確認した）

## 検討した他の案

- 選択時に自動でプレビューまでスクロールする: 一覧に戻るのにまたスクロールが要り、続けて見比べにくい
- 一覧だけを内部スクロールにする: プレビューと一覧の 2 層のスクロールになり、画面が狭い
- 一覧をプルダウン（`<select>`）にする: 感触・時間の補足が見えず、矢印キー相当の前後移動もしにくい。OS 標準の UI で見た目もそろわない
- `zoom` で縮める: 実測で、`transform` と同じく座標がずれた。対応状況も新しい
- 原寸をダイアログ（`<dialog>`）にする: プレビューの DOM（`#stage`）を移すと再生が途切れるため、同じ DOM を CSS で重ねる方式にした

## 結果

- 一覧をスクロールしながら、選んだモーションをすぐ確認できる
- 座標を測るデモを足すときは、`scaleOf(stage)` で補正する必要がある。`tests/viewer.test.js` に、リップルの位置を縮小表示で確認するテストを置いた
- 原寸表示中は、背後の要素にフォーカスが移りうる（フォーカストラップと `inert` は未対応）
