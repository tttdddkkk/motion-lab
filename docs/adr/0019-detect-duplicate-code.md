# 0019: ロジックの重複は共通化し、コピペ検出（jscpd）を CI で強制する

- 状態: 採用
- 日付: 2026-11-16

## 背景

モーションの実装は、AI が似た構造のコードを安く書き足せるため、コピペで増えやすい。実際に、リファクタリング前の `motions.js` と `stories/` には、同じ処理の重複が 12 件（重複率 5.03%）あった。

- `flowSeek` と `withSeek` の再生・シーク実装（38 行の一致を含む）
- 本棚とカードの開閉オーバーレイの状態管理・キー操作
- トーストとバナーの出入りの手順
- `wait` の定義（7 か所）

重複したロジックは、片方だけ直して他方を直し忘れる。CLAUDE.md への記述は「お願い」で強制力がないため、機械で検出できる部分は CI に入れる。

一方で、重複のすべてが悪いわけではない。次のものは、意図して重複させている。

- `code.css` / `code.waapi` は、利用者がコピーする表示用の文字列。`setup` と似ていても共通化しない
- 差分比較のデータ表は、バリアントごとに似た行が並ぶ。「データ定義への追記だけで済む」構造を保つ（ADR 0002）
- 1 モーション 1 オブジェクトで読めること自体が、このリポジトリの価値

## 決定

- 同じ処理（ロジック）の重複は共通化する。データ、表示用コード、モーション固有の演出は対象外
- `jscpd` を CI の `test` ジョブで実行する（`npm run dup`）。設定は `.jscpd.json`
  - 対象は `motions/` `stories/` `tests/` の JavaScript（`motions/types.js` を除く）
  - 4 行・40 トークン以上の同一ブロックが 1 件でもあれば失敗する（`threshold: 0`）
  - 基準ファイル（既存の重複を許容する仕組み）は使わない。導入時点で 0 件にしてから始める
- 構造が似た重複（`--similarity`）と、意味が同じ重複（`--semantic`）は CI に入れない。前者は誤検出が出やすく、後者は約 550 MB のモデルのダウンロードが要る
- 機械で検出できない重複（同じ概念を別の書き方で実装したもの）は、`docs/review-policy.md` の 🟡 WARNING として、PR の自動レビューで見る

## 検討した他の案

- CLAUDE.md に書くだけにする: 強制力がない。判断基準だけを CLAUDE.md に置き、検出は CI に任せる
- 基準ファイル（`--baseline`）で、既存の重複を許容して新規だけ失敗させる: 基準ファイルはハッシュで、どの重複を許容しているか人間に読めない。導入時に 4 件を直して 0 件にしたため不要
- ESLint + `eslint-plugin-sonarjs` で関数単位の重複を検出する: 設定と依存が増える。まず `jscpd` だけで運用し、足りなくなったら再検討する
- 「共通化できるものは全部共通化する」と書く: 偶然似ているだけのコードまで共通化すると、誤った抽象化になる。対象をロジックに限る
- Claude Code の hook でも実行する: 手元でしか効かず、CI が最終ゲートになる。必要になったら別に判断する

## 結果

- 重複したロジックは、PR の時点で `npm run dup` が失敗して見つかる。しきい値は 4 行・40 トークンで、1 行だけの重複（例: 短い定義の繰り返し）は検出できない
- `jscpd` が devDependency に増える（`save-exact`。Dependabot の対象）
- 意図した重複（表示用コード、データ表）は、導入時点では検出されていない（`npm run dup` が 0 件）。新しく意図的な重複を入れて検出されたときは、`.jscpd.json` の `ignore` に足す前に、共通化できないか確かめる
- 検出できるのは文字列とトークンの類似だけ。意味的な重複は、引き続きレビューで見る
