# 0021: ビューアに「何の時間」を表示する（`msLabel`）

- 状態: 採用
- 日付: 2026-11-16

## 背景

`MOTIONS` の `ms` は、ビューアの「時間」欄にそのまま表示される。ところが、`ms` の意味はモーションごとに違う。

- 1 つの文字が枠を横切る時間（流れる文字: 3000 / 4000）
- 1 周の時間（ティッカー帯: 8000）
- 1 文字ごとの間隔（字幕: 80）
- 次の行へ移る時間（同期ハイライト: 300）
- 開き始めから中身が出きるまで（本棚: 1400）

同じ「時間」欄に別の定義の値が並ぶため、モーションどうしを見比べると誤解する。この道具の目的は認識合わせ（`docs/philosophy.md`）なので、数値の意味が曖昧なままでは、数値で指示するときにずれる。

## 決定

- `Motion` に `msLabel`（`ms` が何の時間か）を必須の項目として足す。例:「1周」「1文字ごとの間隔」
- ビューアの詳細に、「時間」の下に「何の時間」の行を出す
- 値は、コードの定数と既存の `desc` から確認できるものだけを書く。推測で書かない
- 型（`types.js` の `Motion`）で必須にして、新しいモーションの定義漏れを `npm run typecheck` で検出する。空文字は `tests/` で検出する

## 検討した他の案

- `ms` を全モーションで同じ意味（全体の長さ）にそろえる: 流れる文字の全体は枠の高さで変わり、字幕の全体は文の長さで変わる。1 つの値で表せないものがある
- 時間欄を `desc` の内訳に寄せる: `desc` は文章で、機械的に表示・比較できない。実装を変えたときにずれやすい
- 現状維持で注記だけ付ける: 注記は読まれにくく、モーションを見比べる場面で効かない
- 時間の欄に「時間（1周）」のように 1 行にまとめる: ラベルが長いと、項目名の列が広がり、スマホ幅の表示が崩れる

## 結果

- 数値の意味がモーションごとに明示され、モーション間の比較での誤解が減る
- モーションを追加するとき、`msLabel` を決める手間が 1 つ増える
- `desc` に書いてある「時間は〜の長さ」と内容が重複する。`desc` は変えていない。実装を変えたときは両方を合わせる必要があり、ずれはテストでは検出できない
- 左の一覧（`feel ・ ◯◯ms`）は、スペースの都合で `msLabel` を出していない。意味は詳細で確認する
