# 0002: 自作ビューアを残し、モーション定義を1か所にまとめる

- 状態: 採用
- 日付: 2026-11-12

## 背景

最も使うのはスマホでの閲覧で、Storybook の管理画面はスマホで見にくい。一方で、ビューアと Storybook でモーションを二重に管理したくない。

## 決定

- `MOTIONS` 配列を `motions/motions.js`、デモ用スタイルを `motions/motions.css` に移し、ビューアと Storybook の両方から読む
- ストーリーは1モーション1行（`export const Xxx = story('<id>')`）にする
- ストーリーの書き忘れは `tests/stories-coverage.test.js` で検出する

## 検討した他の案

- Storybook に一本化する: スマホ向けの専用 UI（再生・速度・コードの3タブとコピー）を失う
- データから全ストーリーを動的に生成する: Storybook はストーリー一覧を静的解析で作るため、標準ではできない

## 結果

- ビューアが ES Modules を使うようになり、`file://` では開けなくなった。GitHub Pages かローカルサーバー経由で開く
- モーション追加時に触るファイルが2つになった（定義本体とストーリー1行）
- `code.css` などの表示用コードと `setup` の実装の一致はテストで検出できない
