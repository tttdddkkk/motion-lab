# 0009: 出先（スマホ）での開発確認を「ブランチ別プレビュー環境＋CI」で行う

- 状態: 採用
- 日付: 2026-11-14

## 背景

- ClaudeアプリのCodeタブからリポジトリに接続したセッションで、コード作成はほぼClaudeに任せられる
- 手元にPCがない状態（スマホ＋モバイルモニタ＋Bluetoothキーボード）で開発したい
- Codeタブのクラウドセッションはアプリがクライアントで、実行はAnthropic管理のクラウド側。そのため、自分のブラウザでローカルサーバーを開いて動作確認する、という使い方はできない
- 主にWebView向けUIを扱うため、見た目と動作の確認手段が必要
- 個人開発のため、管理の手間と壊れやすさを最小にしたい

## 判断基準

1. 出先でPC等の不具合があっても止まらない
2. 運用・管理が軽い（常時起動や定期メンテが不要）
3. 見た目の確認ができる
4. 無料枠または低コストで収まる

## 検討した他の案

### A. 自宅PCでRemote Control

- 手元PCでClaude Codeを動かし、スマホから操作する。ローカルサーバーも通常のテストも従来どおり使える
- ×: PCを起動し続ける必要があり、出先でPCに問題が起きると詰む（基準1を満たさない）

### B. Codespaces上でClaude Code＋Remote Control

- クラウド上の開発マシンでdevサーバーを動かし、ポート転送のURLをブラウザで確認する
- Remote Controlはリモートマシン上のclaudeにも使える（公式ドキュメントにtmux/screen推奨の記述あり）。ただしCodespacesとの組み合わせでの実運用は未検証
- 無料枠は月120コア時間（2コアなら実時間60時間）、ストレージ15GB（2026-11-14 時点、要確認）
- ×: 起動・停止・タイムアウト・枠の管理が必要で、個人利用には管理が重い（基準2）。初期設定もスマホだけでは難しい

### C. ブランチ別プレビュー環境＋CI（採用）

- Vercel / Netlify / Cloudflare Pagesなどでブランチ・PRごとにプレビューURLを発行する
- GitHub ActionsでPRごとにlint・型チェック・テスト・ビルドを実行する
- Claudeはクラウドセッションでブランチ→PRを作り、人間はPRとプレビューURLで確認する
- ○: 壊れる場所が少なく、管理が軽い。スマホとモバイルモニタで完結する
- △: 確認のたびにデプロイ待ちが発生する。実機・WebView固有の挙動はプレビューURLを実機で開いて確認する必要がある

### D. クラウドセッション単体（プレビュー・CIなし）

- ×: 動作確認の手段がなく、基準3を満たさない

## 決定

案Cを採用する。サービスの選定は [ADR 0010](0010-netlify-deploy-preview.md)。運用ルールは CLAUDE.md の「PR 作成後の流れ」に書く。

## 結果

- 壊れる場所が少なく、スマホとモバイルモニタだけで PR とプレビュー URL の確認が完結する
- 確認のたびにデプロイ待ちが発生する
- 実機・WebView 固有の挙動は、プレビュー URL を実機で開いて確認する
