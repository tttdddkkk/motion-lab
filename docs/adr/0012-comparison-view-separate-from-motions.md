# 0012: 認識合わせ用の「差分比較」ビューを、MOTIONS とは別のデータで持つ

- 状態: 採用
- 日付: 2026-11-14

## 背景

このライブラリの存在意義は、見た目の挙動を口頭だけでなく実物で見せ、認識の食い違いを減らすこと。「1つの軸だけを変えた並び」と「口頭で混同しやすいペア」を、実物で再生して比べられるようにしたい。

## 決定

- ビューアに「差分比較」ビューを足す（`index.html` の表示切り替え、URL は `#compare`）。データは `motions/compare.js`、描画は `motions/compare-ui.js`、スタイルは `motions/compare.css`
- 差分比較のデータは `MOTIONS` に入れない。`MOTIONS` はストーリーと「動きを減らす」版の対象（ADR 0001 / 0003）で、比較用のバリアントは目的が違う（1つの動きではなく、同じ動きの違いを見せる）
- バリアントは `params` から、表示する値・実際の動き・コピーする JSON をすべて作る。表示と動きがずれず、追加はデータの追加だけで済む
- 「動きを減らす」設定のときは、代替の動きを出さず再生を止め、その旨を表示する（このページだけ再生するスイッチを置く）。比較の目的が動きそのものを見ることのため、`MOTIONS` の方針（代替版を用意する）とは分ける
- データの整合は `tests/compare.test.js`（DOM なし）で検査する。見た目の差分テストはしない（ADR 0003 のまま）

## 検討した他の案

- `MOTIONS` に追加する: 1バリアントごとにストーリーと「動きを減らす」版が要り、60件規模では負担が大きい。ビューアの一覧も埋まる
- 別ページ（`compare.html`）にする: `netlify.toml` の配信対象を増やす必要があり、ビューアとの行き来も増える
- `index.html` に直接書く: データと描画でファイルが肥大化する

## 結果

- バリアントの追加は `motions/compare.js` にデータを足すだけ
- 差分比較は Storybook の対象外。動作はビューアとテスト（データ整合）で確認する
- 比較用の動きは `MOTIONS` と別にあるため、同じ動きを両方で持つ場合は手で合わせる
- Safari / iOS での WAAPI の挙動は、実機では未確認（Chromium のみ確認）
