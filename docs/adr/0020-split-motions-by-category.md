# 0020: モーション定義をカテゴリ別のファイルに分ける

- 状態: 採用
- 日付: 2026-11-16

## 背景

ADR 0002 で、ビューアと Storybook が読む `MOTIONS` 配列を `motions/motions.js` の 1 ファイルにまとめた。モーションが増え、このファイルは約 1750 行になった。

- 共通の道具（`makeCtx`、`withSeek`、`showNotice`、`createOverlayFlow` など）と 14 モーションの定義が 1 つのファイルに混ざり、読むときにどこまでが共通でどこからがモーション固有か分かりにくい
- モーションの追加は `motions.js` の末尾に集まるため、複数の PR が並ぶと衝突しやすい（CLAUDE.md にも注意として書いていた）

## 決定

- 定義をカテゴリごとのファイルに分ける: `motions/categories/{button,transition,comment,notice,expand,text}.js`。各ファイルは、そのカテゴリのモーションと、そのカテゴリだけが使うヘルパーを持つ
- 複数のカテゴリが使う共通部分は別ファイルにする: `motions/runtime.js`（`makeCtx` と `settle`）、`motions/seek.js`（`withSeek` と `SEEK_BAR`。コメントとテキストが使う）、`motions/dom.js`（`q` / `qa`）
- `motions/motions.js` は入口として残し、カテゴリのファイルを集めて `MOTIONS` を作る。ビューア、ストーリー、テストは、これまでどおり `motions/motions.js` から `MOTIONS` と `makeCtx` を読む
- `MOTIONS` の並び（一覧の表示順）は、これまでと同じ（ボタン → 画面遷移 → コメント → 通知 → 展開 → テキスト）

ADR 0002 の「ビューアと Storybook でモーションを二重に管理しない」「ストーリーは 1 モーション 1 行」は変えない。変わるのは、定義本体を 1 ファイルでなく、入口 1 か所とカテゴリ別のファイルで持つ点だけ。

## 検討した他の案

- 1 ファイルのままにする: 読みにくさと、追記の衝突が残る
- 1 モーション 1 ファイルにする: ファイル数が増えすぎる。同じカテゴリで共有するヘルパー（通知の `showNotice`、展開の `createOverlayFlow` など）の置き場も決めにくい
- データからストーリーを自動で生成する: ADR 0002 のとおり、Storybook は静的解析でストーリー一覧を作るため、標準ではできない

## 結果

- 同じカテゴリのモーションの追加は、そのカテゴリのファイル 1 つ（とストーリー 1 行）で済む。別カテゴリの PR とは衝突しにくい
- 新しいカテゴリを作るときは、ファイルの追加に加えて、`motions.js` の import と `MOTIONS`、`viewer.js` の `CATS`、`types.js` の `MotionCategory` を足す
- 分割の前後で、全モーションの `setup` の関数本体と表示用コードが一致することを、旧ファイルとの突き合わせで確認した
- ヘルパーがカテゴリのファイルに入ったため、別のカテゴリで同じ処理が必要になったら、`runtime.js` などの共通ファイルへ移す（ADR 0019 の重複検出が、同じ処理の重複を CI で見つける）
