# 0013: 流れる文字は、横だけでなく縦（下→上）も作る

- 状態: 採用
- 日付: 2026-11-14

## 背景

[ADR 0008](0008-comment-flow-patent-constraints.md) の決定に「文字は枠の中で横に流す」がある。コメント系のバリエーションとして、同じ「流れる文字+シーク」の方向だけを縦（下→上）にしたものを足したい。決定のこの1項目と食い違うため、見直しを残す。

## 決定

- 流す方向は、横（右→左）のほかに縦（下→上）も許可する。ADR 0008 のこの1項目だけを置き換える
- 縦版も次の条件は ADR 0008 のまま維持する
  - 枠は映像の横または下に置き、映像と重ねない。映像の内側にも置かない（縦版は映像の横に置く）
  - 文字はデモ用の固定テキスト。投稿の仕組みやサーバーは作らない
  - 文字の行は事前に決める。重なりを判定して自動で避ける処理は入れない
  - 特定のサービスの見た目に寄せず、サービス名を使わない
- 縦版の枠は狭いため、長い文字は折り返す（横版は折り返さない）。折り返しで高さが変わるので、終了位置は文字自身の高さ（`translateY(-100%)`）にし、静止表示の行間は2行ぶんにする。デモには2行になる文字を1件入れ、前後の文字との間隔を空けて重ならないようにする（重なりの自動回避は作らない）
- 横版と縦版は実装を共有し、方向だけを切り替える（`motions/motions.js` の `flowSeek`）

## 検討した他の案

- 横だけにとどめる: 縦長の枠での実況・字幕の使い分けを見せられない
- 縦版を別実装にする: 方向以外が同じ動きなので、シーク周りの修正が二重になる

## 結果

- 方向だけが違う2件を並べて比べられる
- 縦方向は、ADR 0008 の請求項との比較では横より遠ざかる（推測。法的な判断ではない）。映像との重なり・投稿・重なりの自動回避を足す変更は、引き続き ADR 0008 を見直してから行う
- 吹き出し（メッセージ系）やテキスト系のモーションは、この ADR の対象外
